# TUT-69 Learning Library

Approved by the founder 2026-10-15 (full run, no stops). Source: Linear TUT-69 + the founder's run prompt.

## Goal
Every generated answer, explanation, notes, story, quiz and EL output is saved per child on the server and shown in "My Library" on the mother/father/family-member and child dashboards. Today only `explain-panel.js` `saveToNotes()` keeps up to 50 explanations in localStorage.

## Design
1. **Table** `learning_items`: see migration. Unique (student_id, mode, content_hash). RLS on, no policies. No "generated by" column.
2. **Writer** `saveLearningItem`: fire-and-forget after the response is sent; failure only logs. Strip base64/`data:` URLs, cap payload 200 KB (skip + log), `content_hash = sha256(mode + payload)`, unique conflict = silent skip. Never from /api/homework-demo or /api/homework-explain. No new model calls, no prompt changes.
3. **Hooks**: /api/homework (homework_help → answer, quiz, storytelling → story, experiential_learning → experiential), /api/explain-please → explain (cache hits too), /api/homework-notes → notes (cache hits too).
4. **Read**: all through `requireOwnStudent` + `item.family_id === session.familyId`. `GET /api/library` (30/page, no payload, subject counts), `GET /api/library/:id` (tier gate: Free = 10 newest open, older 402 with no payload), `PATCH /api/library/:id` (lesson_label ≤ 60, parent only), `POST /api/library/import` (≤ 50 items, mode explain, imported=true). Child sessions never see mode `answer`.
5. **UI**: `library.js` mounts into `#tutpLibrary`; opens items with the existing renderers read-only, plus Save-as-PDF and Listen. Warm empty state.

## What can go wrong (and the test that catches it)
| Risk | Test |
|---|---|
| Item saved under wrong student in a multi-child family | 2: child A item absent from child B list |
| Another family reads an item by id | 1: family B GET family A item → 403 |
| DB failure breaks the homework response | 3: forced insert error, /api/homework still 200 with full answer |
| base64/data: URL or oversized payload stored | 4: no `data:`, size ≤ cap |
| Retry or double click duplicates a row | 5: same request twice → one row |
| Free family reads past the limit | 6: 11 items, oldest 402, no payload in body |
| Child sees answers (parent-only) | 7: child session never gets mode `answer` |
| Import duplicates or loses data | 8: import twice → no duplicates; key removed only after 200 |
| Hidden model call or cost | 9: replay recordings unchanged, cost $0 |
| Same concept, different numbers collides | content_hash covers the full payload, not the concept; covered in 5 with two payloads |
| Same text in two languages | hash includes the payload text, so both save; `language` column set |
| Free vs paid family | 6 plus a paid-family run reading all 11 |
