# Spec: upload-security (pre-approved round)
Audit: one write route, `POST /api/upload` (no check), bucket `family-uploads` (public: it returns `getPublicUrl`), objects named `<ms>-<rand>-<client name>` at the bucket root. Callers: register page (child photo, 5 workbook photos; after OTP, before the family exists), home page attach (before login), teacher page (assignment attachment). No upload reader exists except the teacher attachment link on `/app/child/`; registration photo urls sit in `family_registrations.data` (`children[].photoUrl`, `subjectWorkbooks`) and are never shown again. Stored as full public urls. `id_card_photo_url`/`tutors.photo_url`: no uploader.
1. `server/uploads.js`: type from the file bytes (jpeg, png, webp, heic, pdf; the client type is ignored), 8 MB cap, random names `families/<family_id>/<uuid>.<ext>`, `teachers/<teacher_id>/...`, `registration/<phone hash>/...`; strict path parser, never a client path.
2. `/api/upload` needs a session (family member, or teacher with `purpose: teacher`) else 401; a `studentId` must belong to the session family else 403. Registration uploads need a verified Firebase `regIdToken` (the existing OTP session; no family exists yet) and are moved to `families/<id>/` by `/api/register`, which drops any other path.
3. `GET /api/files/open?path=` (302 or `format=json`): session owner of the path only, then a 15 minute signed url. Stored values are object paths; `toReadable` turns old public urls (and paths) into signed urls in the homework list (the one reader).
4. Home page attach no longer uploads before login: the file waits in sessionStorage and the dashboard takes it from there (it only goes to `/api/homework` as base64 as before).
5. Bucket untouched. `scripts/storage/make-private.ps1` (checks, prints, y/n; needs the new revision to hold traffic) and a count-only mode.
6. Tests: unit (`tests/unit/uploads.test.js`), e2e (`tests/e2e/uploads.spec.js`: no login 401, family A vs B 403 both ways, signed url works then expires, old public-url row displays, wrong type 415), existing homework/explain/check-mistakes specs run unchanged. Preview tag `upsec`, e2e twice, `scripts/release-us.ps1` (not run).
Edge cases: removed member (existing middleware 401); legacy bare paths are never opened through `/api/files/open`; the signing ttl override works only on E2E_REPLAY previews for test families.
